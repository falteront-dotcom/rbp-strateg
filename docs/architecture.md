# Архитектура РБП-Стратег 2.0

Дата: 2026-11-14. База: `master` = `f5e620b` (PR #16–#20 влиты, CI зелёный;
мост к продукту — ветки wt/*, §6).
Аудитория: инженеры, дорабатывающие проект; агенты, выполняющие задачи по коду.
Сверяться с PROJECT-CONTEXT.md (текущее состояние) — этот документ описывает
структуру и решения, не оперативный статус.

## 1. Что это

Next.js-приложение: анализ боевого потенциала (БП) 195 государств. Стратегическая
карта, аналитический комплекс `/v3`, две модели БП (v2 заморожена как контракт,
v3 с неопределённостью и провенансом), досье стран. Стек: Next.js 16 (Turbopack),
React 19, Drizzle 0.45 + better-sqlite3, Tailwind 4, Playwright 1.58, Node 22.

## 3. Слои

### 3.1 UI — `src/app`, `src/components`

Next.js 16 App Router. Стратегический режим (`/`) — карта мира с choropleth БП;
аналитический комплекс `/v3` — рейтинг БП 3.0, карточки стран, системы
вооружений, доска I&W, симулятор войны, методология. Интерактивные компоненты —
`"use client"`. `/v3/methodology` — статическая страница: БД не читает, веса и
концентрация импортируются из `src/lib/bp3/types.ts` и `calculate-bp3.ts`, текст
не может разойтись с кодом (PR #20).

Слой не содержит расчётной логики: страницы и API-роуты вызывают фасад. Окна и
панели используют общий `src/lib/use-dialog.ts` (Escape, ловушка фокуса,
блокировка фона).

### 3.2 Фасад v3 — `src/lib/v3-facade.ts`

Тонкий серверный слой между движками и маршрутом. Три принципа:

1. **Кэш на процесс.** БП 3.0 считается лениво, один раз на процесс
   (`ensureBP3Cache`): Монте-Карло 195 стран × 4000 итераций
   (`DEFAULT_MONTE_CARLO_ITERATIONS`, `src/lib/bp3/calculate-bp3.ts`) — не
   работа для каждого запроса. Сырые итерации (`samples`) нужны только для
   rank-stability когорты и из кэша удаляются.
2. **Мягкие отказы.** Страна, на которой движок упал, пропускается из рейтинга —
   одна битая запись не роняет эндпоинт. Секции детали страны независимы:
   упавшая секция отдаёт `null` (`[]` для торнадо), страница рендерится без неё.
3. **Честность о данных.** Странам вне топ-30 (нет `TOP30_BP3_INPUTS`,
   `src/lib/bp3/data/top30-uav-munitions.ts`) подставляется нулевая базовая
   линия U/P: парки/производство — 0, импортозависимость — 100 %. Строка
   рейтинга несёт `hasUP=false` — потребитель видит нижнюю границу, а не оценку.

### 3.3 Модели — `src/lib/bp`, `src/lib/bp3`

**bp v2 — замороженный контракт** (ADR-0004, PR #17). 8 компонентов
(оружие/люди/логистика/C2/экономика/доктрина/боеготовность/география), веса в
`src/lib/bp/weights.ts`, сумма строго 1.0 (`validateWeights`). bp3 потребляет
баллы v2 как входы (`v2Scores`) — контракт проверяется регрессом
`e2e/bp3-model.spec.ts` («v2Scores is a live contract between generations»).
v2 не пересчитывается и не удаляется.

**bp3 — живая модель** (`MODEL_VERSION_BP3`). Отличия от v2: два новых
компонента войны 2022–2026 гг. — U (БПЛА, 0.10) и P (боеприпасы и оборонное
производство, 0.10), платформенная доля снижена (weapon 0.20 → 0.16); веса
`DEFAULT_WEIGHTS_BP3` — экспертные (см. docs/weights-elicitation.md и
ADR-0003). Каждое входное число несёт провенанс: источник, год, грейд A–E,
флаг оценки; σ входа по грейду — `GRADE_RELATIVE_SIGMA` (0.05…0.45). Итог —
распределение: медиана + P10/P90 по Монте-Карло; веса тянутся из
Dirichlet(κ=100) на каждой итерации, поэтому интервалы покрывают и весовую
неопределённость. RNG — mulberry32 на явном сиде (FNV-1a от isoCode): расчёт
воспроизводим по (входы, веса, сид) на любой машине. Вместе с баллом
публикуются rank-stability (интервал ранга, P(выше соседа)) и торнадо
чувствительности (`src/lib/bp3/sensitivity.ts`).

Диагностики — не калибровка: Spearman против коммитного снапшота GFP
(`src/scripts/diagnostics/spearman-gfp.ts`: ρ=0.876, 132 страны, топ-20
пересечение 17/20) и leave-one-component-out (`loo-ranks.ts`: ρ≥0.991 —
рейтинг переопределён коррелированными компонентами v2-ядра). Отчёты —
`docs/diagnostics/`.

### 3.4 Данные — `src/db`, `src/lib/data*`, `src/scripts`

SQLite **эфемерная**: пересоздаётся при каждом старте процесса
(`src/instrumentation.ts` → `initializeDatabase()`), постоянный диск не нужен
— осознанный компромисс free-тира. Сборка сида: TS-модули
`top20-countries + extended-countries + additional-countries + world-countries`
= 195 стран; БП v2 считается до записи, посев атомарной транзакцией. Пакеты
знаний (техника, досье, сражения, объекты) — идемпотентные сиды;
generated-данные (`src/lib/data/*.generated.ts`) вшиты в бандл.

Версии датасета: каждый успешный посев публикует версию в `dataset_versions`
(`publishSeedDataset`, провалившаяся валидация не публикуется), `/api/health`
сверяет фактические COUNT(*) с эталоном `_seed_meta` (`writeSeedMeta`) — числа
не хранятся в коде, дрейф «ожидали одно — засеяли другое» невозможен по
построению.

Живое обновление — `refreshDatasetFromSources` (World Bank + merge-validate):
один код для CLI (`src/scripts/refresh-dataset.ts`) и `POST /api/run-pipeline`.
Живой сетевой путь в e2e-CI выключен (opt-in `RBP_PIPELINE_E2E`) — свежесть
проверяет отдельный workflow (§3.5).

**Датасет-снапшоты — опт-ин, цикл не включён** (ADR-0002): целевой контур
«pipeline → коммитный JSON-снапшот → ревью → деплой сидом» описан в §6.2,
инфраструктура версий готова, замыкание на прод отложено.

### 3.5 Эксплуатация — `.github/workflows`, `render.yaml`

Прод: Render free, Франкфурт (`render.yaml`). БД производная, без диска.
Сборка требует посеянную БД (`/v3`-страницы читают SQLite на статическом
пререндере), поэтому `buildCommand` —
`npm ci --include=dev && npm run db:seed && RBP_AUTO_SEED=off npm run build`;
`RBP_AUTO_SEED=off` на время сборки исключает гонку пересева с пререндер-воркерами
(«database is locked», воспроизведено). Typecheck при сборке на Render отключён
(`next.config.ts`, `RENDER=true`): typecheck-воркер не влезает в 512 МБ free-тира
(замер OOM при heap 400 МБ); его отдельно гоняет CI.

Надёжность и свежесть — пять контуров:

- **CI** (`ci.yml`, ubuntu-24.04): lint → typecheck → init-db → build →
  db:seed → `npm test` (127 e2e, Playwright chromium). Артефакты отчёта
  выгружаются.
- **Держатель бодрствования**: self-ping `HEAD /api/live` каждые 5 минут из
  самого процесса (`instrumentation.ts`, `RBP_SELF_PING=off` выключает;
  локально — no-op без `RENDER_EXTERNAL_URL`).
- **Внешний watchdog** (`keepalive.yml`, каждые 5 мин): /api/live (лайвнесс),
  /api/health (правда о данных + `commit` — SHA релиза из
  `RENDER_GIT_COMMIT`, присутствует и в 503), SHA прода == master (2 попытки с
  паузой 60 с на идущий деплой). Алерт: issue с меткой `keepalive` +
  Telegram (`TG_BOT_TOKEN`/`TG_CHAT_ID`; секреты не заданы — шаг честно
  предупреждает, issue остаётся запасным каналом). Issue закрывается сам при
  восстановлении. SHA-сверка добавлена в PR #16: старый отпечаток «ровно 195
  стран» не различал релизы.
- **pipeline-refresh** (пн 04:17 UTC): еженедельный живой прогон
  `refresh-dataset.ts` — ловит протухание URL/форматов источников до аварии.
  После прогона экспортируется датасет-снапшот; при изменении payload бот
  коммитит его в master (§6.2) — прод обновляется через обычный деплой.
  Алерт — issue `pipeline-rot`.
- **keepalive-tick** (1-е числа): пустой коммит `[skip ci] [skip render]` в
  боковую ветку против 60-дневного автоотключения cron GitHub.

Известный разрыв: прод до сих пор на билде от 7 октября 2026 (`65d483d`) —
новый `buildCommand` из `render.yaml` сервис Render не подхватил (сервис,
видимо, не через Blueprint либо переопределён в Dashboard), применение
отложено хозяином. Диагностика и критерии готовности — PROJECT-CONTEXT.md,
раздел «Прод: стейл-билд и диагноз». Архитектурно правильный сигнал уже есть:
keepalive SHA-сверки красный ровно на этот случай.

Инварианты слоёв: весов (сумма 1.0) — моделями; воспроизводимость Монте-Карло —
сиды в `uncertainty.ts`; контракт v2Scores — регрессом e2e; целостность сида —
`_seed_meta` + `/api/health`.

## 5. Пути развития после шагов 0–4

Дорожная карта пузыря 2026-11-13 исполнена шагами 0–4 (PR #16–#20). Дальше три
не конкурирующих пути:

**A. Глубина (модель).** Исполнено: честность модели (Dirichlet-веса,
rank-stability, P10/P90 — PR #18), диагностика (Spearman, LOO — PR #19),
методология (`/v3/methodology`) и досье (`/api/v3/dossier`, Markdown с
провенансом и интервалами — PR #20). Дальше: экспертная elicitation весов
(BWM или Дельфи; процедура и приёмка — docs/weights-elicitation.md);
калибровка по исходам — **только при появлении подлинных исходов** (Bradley–Terry
на диадных исходах COW MID 5.0 с walk-forward holdout), не по GFP.

**B. Продукт (спрос).** Public API v1 + досье + еженедельный дайджест как
проверка спроса: дёшево, на существующем фасаде, без новой инфраструктуры.
Платный тир — только после доказанного спроса (замер обращений/подписок).
Остаёмся на Render free: без SLA (см. §6.4).

**C. Платформа (надёжность).** Снапшоты данных (§6.2), деплой-надёжность —
код готов (`render.yaml`, SHA-сверка, отпечаток в `/api/health`), применение
отложено до доступа к Render Dashboard/API-ключу; мониторинг — TG-секреты не
заданы, внешний UptimeRobot на `/api/health` не поставлен (cron GitHub
голодает: ~1 запуск в 11 ч вместо 5 мин, замер по истории прогонов).

## 6. Мост к продукту (реализован, ветки wt/*)

Мост = три добавления к текущим слоям, без их перестройки.

### 6.1 Public API v1 (ADR-0001, реализовано)

Read-only API за стабильным префиксом `/api/public/v1/`:
`countries` (БП 2.0, та же БД и маппер, что `/api/countries`), `ranking`
(БП 3.0 с интервалами P10–P90 и rank-stability), `dossier?iso=` (общий
построитель `src/lib/dossier.ts` с `/api/v3/dossier`), `meta` (паспорт модели:
веса, κ=100, источники, покрытие). Версионирование — в пути; изменения внутри
v1 только аддитивные, ломающие — v2 с периодом параллельной жизни. Rate-limit
per-IP (token bucket на процесс; сброс при рестарте free-инстанса — заявлено
честно, как ограничение; изоляция по IP только при доверенном XFF). Кэш фасада
уже делает ответы дешёвыми — новой вычислительной нагрузки нет. Это API
«как есть», без SLA. Контракт — `docs/API.md`, регресс —
`e2e/public-api.spec.ts`.

### 6.2 Датасет-снапшоты (ADR-0002, реализовано; включение на проде отложено)

Контур обновления данных замкнут через git:

```
pipeline-refresh (живой прогон источников)
        │  export-dataset: БД → JSON (payload без изменений → файл не трогаем)
        ▼
бот-коммит «data: weekly dataset snapshot» → push в master (без ревью)
        │
        ▼
деплой (обычный push master) → сид из снапшота (opt-in RBP_SEED_SNAPSHOT=on)
        → dataset_versions
```

Авто-коммит без ревью — принятый риск (источник публичный и машинный, откат
тривиален, ревью-цикл на free-тире с одним мейнтейнером сделал бы свежесть
недостижимой); см. docs/data-snapshots.md. Потребление снапшота в bootstrap —
строго опт-ин: дефолт — канонические TS-сиды, контракты e2e не меняются;
невалидный снапшот — явная ошибка. Включение на проде — после деплой-надёжности
(применить `render.yaml`), отдельным решением хозяина.

### 6.3 Дайджест (реализовано)

Еженедельный контент-артефакт из данных фасада: топ-10 рейтинга с интервалами
P10–P90 и ранг-устойчивостью, самые неопределённые соседние пары, лента
мониторинга, методологический футер. Генератор `src/lib/digest/generator.ts`
(один вход для Markdown и страницы), CLI `src/scripts/generate-digest.ts`,
страница `/v3/digest`, история выпусков в `docs/digests/` (первый выпуск
сгенерирован из реальной БД). Назначение — проверка спроса контентом до
инвестиций в API-инфраструктуру; каналы (TG/рассылка) — после первых выпусков.

### 6.4 Что сознательно НЕ делается

| Не делаем | Почему |
|---|---|
| Публичный SLA-API на Render free | Инстанс засыпает (первый запрос до ~45 с), сборка OOM на 512 МБ, cron голодает. Обещать SLA на этом тире — врать. Сначала спрос (B), потом тир |
| Калибровка весов по GFP | Циркулярность: GFP — сам композит с закрытыми весами; подгонка к нему переоткрывает чужие экспертные веса (docs/weights-elicitation.md). GFP остаётся диагностикой |
| Удаление bp v2 | v2 — живой контракт bp3 (`v2Scores`); регресс `e2e/bp3-model.spec.ts` уронит удаление. Пока живёт bp3 — живёт v2 (ADR-0004) |
| Нативный PDF-рендер досье | Цена зависимости (headless-рендер в бандле/сборке) против печати страницы браузером. Решение — Markdown + печать (PR #20, комментарий в `src/app/api/v3/dossier/route.ts`) |

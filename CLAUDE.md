## 1. Что это за проект

**РБП (Расчёт Боевого Потенциала)** — тактический симулятор анализа боевой эффективности военной техники. Приложение позволяет размещать, управлять и моделировать взаимодействие боевых единиц трёх сторон (NATO, РФ, КНР) на интерактивной голографической карте.

**Ключевые возможности:**
- Размещение 50+ реальных единиц техники (Су-57, F-35, Т-14, AbramsX и др.)
- Управление движением через вейпоинты и тактические построения
- Расчёт «Обобщённого Боевого Статуса» (ОБС) на основе ТТХ
- Монте-Карло симуляция вероятности победы 1v1
- Конструктор кастомных юнитов с реальными параметрами
- Голографический интерфейс с кинематографическими эффектами

## 3. Архитектура

### 3.0 Двухрежимная модель (Стратегический + Тактический)

Приложение работает в **двух режимах**. **Стратегический** — режим по умолчанию.

| Режим | Компонент | Описание |
|-------|-----------|----------|
| **Стратегический (DEFAULT)** | `page.tsx` + `StrategicMap` + `CountryCard` | Реальная карта мира (Mapbox+Deck.gl), choropleth БП, боковые панели со странами и аналитикой |
| **Тактический** | `TacticalHUD` | Размещение юнитов, вейпоинты, построения, ОБС, симуляция боя |

Переключение между режимами — кнопка в top bar.

## 4. Ключевые файлы и их роль

### 4.1. `src/lib/rbp-engine.ts` — Мозг симуляции

**Класс `RBPEngine`** управляет:
- **Физикой движения**: векторы скорости (`vx`, `vy`), демпфирование, сила разделения
- **Состояниями юнитов**: `IDLE` → `MOVING` → `FORMATION` → `ENGAGING`
- **Построениями**: `LINE`, `WEDGE` (V-образное), `COLUMN`, `DIAMOND`
- **Модификаторами среды**: погода и РЭБ влияют на авиацию и ПВО
- **60 FPS рендерингом**: прямая манипуляция DOM (обход React для плавности)

**Важно**: Движок использует `requestAnimationFrame` и напрямую манипулирует DOM-узлами маркеров для достижения 60 FPS. React state обновляется throttle'ом (~10 FPS) для UI.

### 4.2. `src/lib/unit-database.ts` — Арсенал

**50+ реальных единиц** с категориями:
- `aircraft` — Истребители, бомбардировщики, ДРЛО, БПЛА
- `ground` — Танки, БМП, САУ
- `air_defense` — ЗРК различных дальностей

**Стороны (Side)**: `NATO` | `RUS` | `CHINA`

**Расчёт ОБС (функции):**
- `calculateGroundPotential()` — на основе мощности, массы, брони, калибра, пробития
- `calculateAirPotential()` — на основе тяги, веса, скорости, ЭПР (RCS), дальности ракет
- `calculateADPotential()` — на основе дальности радара, перехвата, скорости ЗУР

**Модули улучшений:**
| Модуль | Для | Эффект |
|--------|-----|--------|
| `era` | Наземные | +30% к броне (ДЗ) |
| `aps` | Наземные | КАЗ, +10% ОБС |
| `stealth` | Авиация | ЭПР -80%, дальность ракет -20% |
| `beast` | Авиация | ЭПР +400%, дальность ракет +30% |

**Монте-Карло симуляция:** `simulateEngagement(unitA, unitB, iterations=1000)` — стохастическая модель с учётом вероятности попадания и работы КАЗ.

### 4.3. `src/components/TacticalHUD.tsx` — Главный интерфейс

**Единый компонент**, содержащий:
- **Верхнюю панель**: заголовок, статус, часы (WGS-84 / GLONASS-M)
- **Левую панель**: выбор юнита, развёртывание, список активных сил, **Intel Card** (анализ выбранной группы)
- **Центр**: голографическая карта с юнитами, вейпоинтами, выделением рамкой
- **Правую панель**: сводка потенциалов сторон, погода/РЭБ, тактический лог

**Управление:**
- Клик по карте — назначить вейпоинт (один юнит) или построение (группа)
- Shift+клик — множественное выделение
- Двойной клик по юниту — выделить все юниты того же типа
- Box selection — выделение рамкой

### 4.4. `src/components/ComparisonMatrix.tsx` — Аналитика

**Модальное окно** для сравнения двух юнитов:
- Выбор из выпадающих списков
- Радарная диаграмма (5 параметров)
- Сравнение ТТХ с дельтой в процентах
- **Монте-Карло прогноз**: полоса вероятности победы A / взаимоуничтожение / победа B
- Индекс эффективности (ОБС на $1M)

### 4.5. `src/components/CustomUnitBuilder.tsx` — Конструктор

**Создание собственных юнитов:**
- Ввод названия, страны, категории, роли
- Параметрические слайдеры для всех ТТХ
- Модули (ДЗ, КАЗ, Stealth, Beast)
- Автоматический расчёт ОБС
- Экспорт/импорт JSON всего арсенала

## 7. Правила работы с кодом (для AI-агентов)

### 7.1. Приоритеты
1. **Type Safety** — строгая типизация, без `any`
2. **Двухрежимность** — Стратегический режим = DEFAULT. Тактический доступен через toggle
3. **Физика** — изменения в `rbp-engine.ts` требуют проверки на 60 FPS плавность
4. **Баланс** — изменение формул БП влияет на все страны, проверять через CountryCard + RadarChart
5. **Локализация** — новые строки добавлять в `TRANSLATIONS` в `i18n.ts`
6. **`use client`** — все интерактивные компоненты обязаны иметь `"use client"` директиву (page.tsx, CountryCard, TacticalHUD, map/*)

### 7.2. Что НЕ делать
- Не использовать стандартный `setState` для анимации маркеров (ломает 60 FPS)
- Не менять структуру `ARSENAL` без обновления `calculateCustomPotential()`
- Не добавлять юниты без реалистичных ТТХ (проверять по открытым источникам)
- Не забывать `use client` для компонентов с интерактивностью
- Не удалять существующий тактический код (TacticalHUD, HolographicMap, DuelSimulator)
- Не менять `page.tsx` так, чтобы Стратегический режим перестал быть дефолтным
- Не хардкодить Mapbox-токен — только через `NEXT_PUBLIC_MAPBOX_TOKEN` в `.env.local`

### 7.3. При добавлении нового юнита
1. Добавить в `rawArsenal` в `unit-database.ts`
2. Указать `stats` с реалистичными ТТХ
3. Запустить `calculateCustomPotential()` для проверки ОБС
4. Добавить перевод в `TRANSLATIONS.icons` если новый `iconType`
5. Проверить в ComparisonMatrix с аналогами

### 7.4. При изменении UI
- Использовать цвета из палитры OKLCH, не хардкодить hex
- Сохранять `glass-panel` и `tactical-corner` стили
- Тестировать на контрастность (тёмный фон + яркие акценты)
- Добавлять `AnimatePresence` для анимированных появлений/исчезновений

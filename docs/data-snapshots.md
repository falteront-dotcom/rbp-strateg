# Датасет-снапшоты: мост «живой pipeline → коммитные данные»

Обновлено: 2026-11-14.

## Проблема

На Render free диск эфемерный: БД пересоздаётся из коммитных сидов при каждом
старте процесса. Живой pipeline (`refreshDatasetFromSources`, World Bank +
merge-validate) обновлял только БД раннера CI — его результат до прода не
доезжал вообще. Прод-данные оставались сном в TS-сидах со дня последней
ручной правки.

## Механизм

```
живые источники
  → refreshDatasetFromSources (БД раннера, БП считается тем же движком)
  → src/scripts/export-dataset.ts
      БД → src/db/seed/generated/dataset-snapshot.json (коммитный файл)
  → pipeline-refresh.yml: если diff — бот-коммит «data: weekly dataset snapshot» в master
  → Render деплоит; при старте bootstrap сеет страны из снапшота
      (src/db/seed/snapshot-loader.ts, opt-in)
```

Формат снапшота (`DatasetSnapshot`, см. `snapshot-loader.ts`):

- `version` — версия формата (1);
- `exportedAt` — ISO-время экспорта;
- `seedMeta` — содержимое `_seed_meta` (COUNT строк таблиц на момент экспорта);
- `countries` — полные строки таблицы countries (44 колонки, включая `bp_*`),
  отсортированы по `iso_code` для стабильного git-diff.

Экспорт самопроверяется той же валидацией, что и загрузка: файл на диске
всегда пригоден к потреблению.

## Как включить на проде (Render)

1. В окружении сервиса Render задать `RBP_SEED_SNAPSHOT=on`.
2. Всё. При каждом старте процесс сеет страны из коммитного снапшота;
   пакеты знаний (`seedKnowledge`) сеются как обычно; БП не пересчитывается —
   строки пишутся как есть, включая `bp_*`, вычисленные раннером.

**По умолчанию (флаг не задан) поведение прежнее: канонические TS-сиды,
195 стран.** Это осознанный opt-in: e2e-фикстуры (значения USA, число стран,
топ-рейтинг) опираются на TS-сиды, и тихая смена источника сломала бы
контракты. Ветка снапшота меняет только `countries` — знания и метаданные
идут тем же кодом.

При включённом флаге битый или отсутствующий снапшот — **явная ошибка сида,
не тихий фолбэк**: `/api/health` покажет 503, ручной пересев `/api/init-db`
упадёт с `[dataset-snapshot] …`. Молчаливый откат на устаревшие TS-сиды под
видом свежих данных считаем хуже видимого отказа.

Технический путь снапшота: `RBP_SNAPSHOT_PATH` (по умолчанию
`src/db/seed/generated/dataset-snapshot.json` относительно cwd процесса).

## Как обновлять

- **Автоматически:** workflow `pipeline-refresh` (понедельник 04:17 UTC) —
  живой refresh + экспорт + бот-коммит diff в master с сообщением
  `data: weekly dataset snapshot`. Без изменений файла коммита нет.
- **Вручную из канонического сида:**
  `npm run db:seed && npx tsx src/scripts/export-dataset.ts` — пересобрать
  снапшот после правки TS-сидов и закоммитить.
- **Вручную из живых источников:** `npm run db:seed && npx tsx src/scripts/refresh-dataset.ts`
  (refresh сам вызывает экспорт) — проверить diff глазами перед коммитом.

## Риски и границы

- **Лаг в один деплой.** Прод получает свежие данные только после деплоя
  коммита бота, не мгновенно из источника.
- **Конфликты с ручными правками сидов.** Если TS-сиды правили, а снапшот
  не пересобрали, бот закоммитит поверх расходящуюся версию — расхождение
  разруливает хозяин репо (бот не делает rebase/force-push).
- **Окно валидации 150–250 стран.** Снапшот с числом стран вне окна
  отвергается — защита от обвала источника (протухший URL отдаёт 0 строк).
- **Данные World Bank в проде без ревью.** Бот-коммит публикует то, что дал
  живой источник; аномалии значений ловит валидация датасета
  (`validateCountryDataset` внутри загрузчика), но содержательную правдивость
  никто не ревьюит. Не включайте `RBP_SEED_SNAPSHOT=on`, если это неприемлемо.
- **`updated_at` в снапшоте** — дата данных источника, не дата коммита;
  свежесть смотри по `exportedAt`.

## Регресс-тесты

`e2e/dataset-snapshot.spec.ts` (11 тестов): round-trip «канонический сид →
экспорт → загрузка → строки совпадают», явное отвержение невалидных снапшотов
(битый JSON, структура, окно стран, дефектные поля, дубликаты), неизменность
дефолтного bootstrap (195 стран без флага), opt-in ветка через
`RBP_SEED_SNAPSHOT=on` (валидный → сид из снапшота; битый → падение без
фолбэка). Временные БД — в `os.tmpdir()`.

# ADR-0002: Датасет-снапшоты — опт-ин (pipeline → коммит → деплой)

Дата: 2026-11-14
Статус: **реализовано** (ветка wt/dataset-snapshots); включение на проде
отложено — нужен `RBP_SEED_SNAPSHOT=on` в окружении Render

## Контекст

БД на проде эфемерная: пересоздаётся из коммитных сидов при каждом старте
(`src/instrumentation.ts` → `initializeDatabase()`). Свежесть прод-данных =
дисциплина ручного обновления коммитных сидов — осознанный компромисс free-тира
(`src/db/bootstrap.ts`, комментарий в `src/scripts/refresh-dataset.ts`).

Живой путь обновления существует и работает (`refreshDatasetFromSources`:
CLI `refresh-dataset.ts` ≡ `POST /api/run-pipeline`), еженедельный
`pipeline-refresh.yml` гоняет его против живых источников — но результат живёт
только в БД раннера. Цикл «источник → прод» не замкнут: обновить сиды может
только человек руками.

Инфраструктура версий датасета готова: `dataset_versions` +
`publishSeedDataset()` (каждый успешный посев публикует версию; провалившаяся
валидация не публикуется), `/api/dataset/health` и `/api/dataset/versions`
говорят правду на свежем старте (e2e: `dataset-publisher.spec.ts`,
`dataset-lifecycle.spec.ts`).

## Решение

Замкнуть цикл обновления данных через git:

```
pipeline-refresh (живой прогон источников)
        │  export-dataset: БД → JSON-снапшот (payload без изменений → файл не трогаем)
        ▼
бот-коммит «data: weekly dataset snapshot» → push в master (без ревью)
        │
        ▼
обычный деплой (push master → Render) → посев из снапшота (opt-in
RBP_SEED_SNAPSHOT=on) → dataset_versions
```

Решение об авто-коммите принято осознанно: данные World Bank попадают в прод
без ревью человеком. Основания: источник публичный и машинный, объём diff
ограничен снапшотом, откат тривиален (`git revert`), а ревью-цикл на free-тире
с одним мейнтейнером сделал бы свежесть недостижимой. Риск принят и
задокументирован (docs/data-snapshots.md); при появлении платного тира или
команды гейт ревью можно вернуть без изменения формата.

Потребление снапшота в bootstrap — строго опт-ин (`RBP_SEED_SNAPSHOT=on` +
валидный снапшот); дефолт — канонические TS-сиды, контракты e2e не меняются.
Невалидный снапшот — явная ошибка, без тихого фолбэка. Откат данных =
`git revert` снапшота. Опт-ин сохраняется и в CI (живой прогон в e2e —
`RBP_PIPELINE_E2E`).

## Последствия

**Плюсы:** обновление данных становится видимым diff'ом с авторством и
датами (`dataset_versions` + git); откат тривиален; свежесть не зависит от
ручной дисциплины.

**Минусы/риски:** данные World Bank в проде без ревью (принятый риск);
дифф-шум в истории репозитория; JSON-снапшоты в git — дисциплина размера;
задержка «источник → прод» — цикл «weekly прогон → деплой».

**Включение на проде отложено, потому что:** сначала деплой-надёжность
(стейл-билд прода, применить `render.yaml`); снапшоты не блокируют мост к
продукту (API v1, дайджест).

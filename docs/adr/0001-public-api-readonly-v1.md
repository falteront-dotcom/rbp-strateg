# ADR-0001: Public API v1 — read-only, rate-limit, без SLA

Дата: 2026-11-14
Статус: **предложено** (часть «моста к продукту», не реализовано)

## Контекст

Прод — Render free (`render.yaml`): инстанс засыпает после ~15 минут тишины
(первый запрос потом до ~45 с), память 512 МБ, cron GitHub голодает (~1 запуск
в 11 ч вместо 5 мин, замер по истории прогонов). Спрос на внешний API не
доказан: продукта «API для потребителей» ещё нет, есть UI и досье в Markdown
(`GET /api/v3/dossier?iso=XXX`, PR #20). Существующие маршруты `/api/v3/*`
обслуживают собственные страницы и меняются вместе с UI — опираться на них
внешним потребителям нельзя: сегодня поле переименуют под вёрстку, завтра
сломается чужая интеграция.

Кэш фасада (`src/lib/v3-facade.ts`) уже считает БП 3.0 один раз на процесс —
дополнительные читатели почти бесплатны для вычислений.

## Решение

Открыть публичный read-only API за стабильным префиксом `/api/v1/`:

- подмножество фасада: рейтинг БП 3.0, деталь страны, досье, методология;
- версионирование в пути (`/api/v1/...`): внутри v1 — только аддитивные
  изменения; ломающие — v2 с периодом параллельной жизни;
- rate-limit per-IP (счётчик на процесс; сбрасывается при рестарте free-инстанса —
  заявляем как ограничение, а не скрываем);
- без аутентификации на чтении, без ключей;
- позиционирование: «as is», без SLA.

API v1 + дайджест (ADR-контекст §6.3 docs/architecture.md) — инструмент
проверки спроса. Платный тир и SLA — только после доказанного спроса
(замер обращений/подписок), и тогда уже на платформе, которая их держит.

## Последствия

**Плюсы:** контракт внешних потребителей фиксируется отдельно от UI-маршрутов;
дёшево (кэш уже есть); спрос измеряется до инвестиций.

**Минусы/риски:** rate-limit в памяти неточен (много процессов/рестарты);
бесплатный тир может лечь под неожиданной нагрузкой — закрывается лимитом и
отсутствием обещаний SLA; поддержка обратной совместимости v1 становится
обязанностью.

**Обязательства:** регресс-тесты контракта v1 (e2e, как у
`e2e/bp3-model.spec.ts` для v2Scores); изменения схемы ответа — только
аддитивные внутри v1.

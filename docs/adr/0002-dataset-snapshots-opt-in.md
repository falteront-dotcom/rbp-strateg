# ADR-0002: Датасет-снапшоты — опт-ин (pipeline → коммит → деплой)

Дата: 2026-11-14
Статус: **принято, включение отложено** (инфраструктура версий готова, контур
на прод не замкнут)

## Контекст

БД на проде эфемерная: пересоздаётся из коммитных сидов при каждом старте
(`src/instrumentation.ts` → `initializeDatabase()`). Свежесть прод-данных =
дисциплина ручного обновления коммитных сидов — осознанный компромисс free-тира
(`src/db/bootstrap.ts`, комментарий в `src/scripts/refresh-dataset.ts`).

Живой путь обновления существует и работает (`refreshDatasetFromSources`:
CLI `refresh-dataset.ts` ≡ `POST /api/run-pipeline`), еженедельный
`pipeline-refresh.yml` гоняет его против живых источников — но результат живёт
только в БД раннера. Цикл «источник → прод» не замкнут: обновить сиды может
только человек руками.

Инфраструктура версий датасета готова: `dataset_versions` +
`publishSeedDataset()` (каждый успешный посев публикует версию; провалившаяся
валидация не публикуется), `/api/dataset/health` и `/api/dataset/versions`
говорят правду на свежем старте (e2e: `dataset-publisher.spec.ts`,
`dataset-lifecycle.spec.ts`).

## Решение

Замкнуть цикл обновления данных через git, опт-ин на каждом шаге:

```
pipeline-refresh (живой прогон источников)
        │  выгрузка diff'а сида против текущего коммита
        ▼
коммитный JSON-снапшот → ревью человеком → merge в master
        │
        ▼
обычный деплой (push master → Render) → посев из снапшота → dataset_versions
```

Ни один живой прогон не меняет прод автоматически: человек видит и одобряет
diff до деплоя. Откат данных = `git revert` снапшота. Опт-ин сохраняется и в
CI (живой прогон в e2e — `RBP_PIPELINE_E2E`).

## Последствия

**Плюсы:** обновление данных становится ревьюимым diff'ом (сейчас — молчаливая
ручная правка сидов); история изменений данных получает авторство и даты
(`dataset_versions` + git); откат тривиален.

**Минусы/риски:** дифф-шум в истории репозитория; JSON-снапшоты в git —
дисциплина размера; задержка «источник → прод» не меньше цикла ревью.

**Отложено, потому что:** текущий приоритет — мост к продукту (API v1,
дайджест) и деплой-надёжность (стейл-билд прода, применить `render.yaml`);
снапшоты не блокируют ни то, ни другое.
